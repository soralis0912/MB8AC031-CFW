# ARM のコアで走るプログラム

ARM-E / ARM-C に載せる、こちらのプログラムです。主 FR の `CFW` とも、
補助ユニットの `src/auxcore/` とも別のイメージで、命令セットも ARM で別です。
`arm-none-eabi` でビルドします（[`../../docs/toolchain.md`](../../docs/toolchain.md)）。

ARM の帯の番地と、実測した事実は [`../../docs/arm.md`](../../docs/arm.md) にあります。
ここでは、2 つのコアの使い分けと、そのためのファイルの構成を説明します。

## 2 種類のコア

このチップでこちらが動かせる CPU は 2 種類あります。

| コア | 何か | こちらのイメージ |
|---|---|---|
| 主 FR | チップ全体を制御します。USB の口とつながっています | `src/main/`（`CFW`） |
| ARM（ARM-E・ARM-C の 2 基） | ARM926EJ-S。主 FR の窓から ITCM にイメージを書いて走らせます | ここ（`src/armcore/`） |

ここでは、主 FR と ARM 1 基を組にして使います。ARM-E でも ARM-C でも、同じイメージが
同じように走ります（GV-M2TV で実測。違うのは窓だけです）。

## 主 FR と ARM の仕事の分け方

主 FR と ARM は、待つ仕事かどうかで仕事を分けます。

- 主 FR は待ちません。USB の `FRQ1` の枠に答え、TS を流し、チップの電源と
  ゲートを扱い、ARM にイメージを載せます。ARM への依頼を輪に入れ、答えを輪から
  出すのも主 FR です。どれもその場で終わります
- ARM は待つ仕事を受け持ちます。条件が立つまで見張る、値が変わったら知らせる、といった
  時間のかかる仕事を、自分のループで回します

主 FR には自分のループがありません。CFW はホストの枠が来たときだけ走り、答えたら戻ります
（`src/main/stream.c` の注記）。主 FR だけで待つ仕事をするときは、`FW_EAGAIN` を返して
ホストに繰り返し呼んでもらいます。

## 動作の要点

- USB の端点は主 FR が扱い、TS も主 FR が流します。ARM から EP `0x81` へ書くと、
  EP0 の転送と重なったときに TS が数バイトずつ欠けます（GV-M2TV で実測。
  [`../../docs/arm.md`](../../docs/arm.md) の「TS を流すコア」）。EP0 に答える常駐ローダは
  主 FR にいるので、端点の窓は主 FR だけが触ります
- 周辺のブロックは、1 つにつきどちらか一方のコアだけが持ちます。同じブロックを両方のコアから触りません。
  ARM に任せたブロックは、主 FR は ARM に頼んで触ります。`0x00F10090` の
  ような順番待ち（未確認）は使いません（主 FR から読むと壊れるという実測があります。`../shared/mb86m01.h`）
- 輪は 2 本で、1 語の書き手は 1 人です。依頼の輪（主 FR → ARM）と答えの輪
  （ARM → 主 FR）があり、頭は作る側だけが、尻は取る側だけが書きます。そのため鍵が要りません。
  形は [`../shared/armipc.h`](../shared/armipc.h) 1 本にまとめてあり、両方のコアとホストの
  サンプルが同じものを読みます
- 割り込みは使いません。ARM は主 FR の割り込みの要因（`0x00FD0038`、ARM-C は `0x00FD0034`）を
  立てられます（GV-M2TV で実測）。ただし、主 FR がそれを割り込みとして受ける形は未確認で、
  主 FR は割り込みの入口を持っていません（[`../../docs/arm.md`](../../docs/arm.md) の「割り込み」）。
  主 FR はホストの枠が来たときに輪を見ますし、ARM も輪を見て回るので、割り込みが無くても動きます。
  止め方は下の「止め方」にあります
- 1 歩の中では待ちません。サービスは 1 周に 1 歩だけ進めて戻ります。条件が立って
  いなければ、次の周にまた見ます。割り込み無しで止められるのはこのためです
- 郵便受けと輪は分けています。DTCM の最後の 256 バイトの郵便受け（`diag.c`）は、
  生きているか・落ちたか・1 回の読み書き、だけを扱います。仕事は輪（`ipc.c`）で頼みます。
  輪が壊れたときも、郵便受けは答えます
- 時間はループの回数で数えます。この ARM のタイマーはまだ分かっていません。
  ミリ秒で指定する待ちは `IPC_PASSES_PER_MS`（1800 周）で数えます。1800 周は 1 周を
  0.556 µs とした数です。1 周の実際の長さはこれより長いので（GV-M2TV で実測）、待ちが頼んだ長さより
  短くなることはありません。
  `WAIT` の期限も回数で指定します
- キャッシュと MMU は切ったままです。主 FR と DTCM を共有するので、
  キャッシュを切っているので、掃除は要りません
- 語より狭い書き込みはしません。輪のどの欄も 1 語です。dione の窓は語でしか
  書けません
- 同じイメージを両世代で使います。ARM は selene・dione とも ARM926 で、窓の番地も同じです。
  世代で違うのは、主 FR が帯を起こす手順だけです（`../main/arm_dione.c`・`arm_selene.c`）

## 止め方

割り込みが無くても、仕事は終わらせられます。止め方は強い順に 3 段あります。

| 段 | どう止めるか | 効かないとき |
|---|---|---|
| 1. `STOP` を輪で送る | 次の周でサービスが読みます。止まったことは答え（`STOPPED`）で返ります | 依頼の輪が満杯のとき、または答えの輪が満杯で ARM が依頼を取らないとき |
| 2. 止め語（`ARM_CANCEL`、`0x66`） | 輪の外の語です。ARM は毎周いちばん先にこれを見るので、輪がどうなっていても効きます。SEQ を 1 つ指すか、全部（`IPC_CANCEL_ALL`）を指します。全部の場合は、まだ取っていない依頼も捨てます。答えは返さず、終わらせた数と捨てた数を見出しに書きます | ARM のイメージそのものが止まっているか、暴走しているとき |
| 3. `ARM_HOLD` | コアごと止めます（`0x00E70000` の bit0、実測） | 効かないことはありません。ただし仕事の途中で切れるので、周辺を持つ仕事では事故のときだけ使います |

止め語でも、1 語の書き手は 1 人です。主 FR が `CANCEL_WHAT` と `CANCEL_REQ` を書き、
ARM が `CANCEL_DONE`・`CANCEL_DROPPED`・`CANCEL_ACK` を書きます。ARM は最後に
`CANCEL_ACK = CANCEL_REQ` とするので、主 FR は ACK を見れば止めが済んだと分かります。
前の止めが済むまで、主 FR は次の止めを受け付けません（`FW_EAGAIN`）。

割り込みが必要になるのは、ARM が長い計算を区切らずに回すときと、1 µs より速く
ハードウェアに応える必要があるときです。前者は 1 周 1 歩に区切れば済み、後者は今の仕事にはありません。

## 流れ

```
ホスト                     主 FR（src/main/arm_ipc.c）      ARM（src/armcore/）
  |  ARM_CALL (0x64) ------> 依頼を輪に入れて REQ_HEAD++
  |  <-- SEQ を返す（すぐ）                                  ループが依頼を取る
  |                                                          すぐ答えるもの → 答えの輪へ
  |                                                          待つもの → 見張りを始める
  |  ARM_REAP (0x65) ------> 答えの輪が空 → E_AGAIN（すぐ）
  |       ...                                                条件が立った → 答えの輪へ
  |  ARM_REAP (0x65) ------> 答えを 1 つ出して REP_TAIL++
  |  <-- SEQ・状態・値
```

主 FR はどの枠でも待ちません。待っているのは ARM だけです。

## DTCM の中（ARM から見た番地）

```
0x00100000  .bss（svc_watch.c の見張りの表など）
     ...    スタック（下へ伸びる）
0x0010F600  置き場（armipc.h）    送り側 0x200（主 FR が書く）・受け側 0x200（ARM が書く）
0x0010FA00  仕事の輪（armipc.h）  見出し 64 B（止め語を含む）・依頼 16 枠・答え 16 枠
0x0010FF00  郵便受け（armcore.h）  ALIVE・LOOPS・FAULT・1 回の読み書き
0x00110000
```

主 FR からは、窓の `+0x80000` 帯に同じ並びで見えます（ARM-E なら `0x00E8FA00`）。

## サービス

番号と引数は [`../shared/armipc.h`](../shared/armipc.h) にあります。

| サービス | 操作 | 答え |
|---|---|---|
| `SYS` | `ECHO` | すぐ。`~arg0` とデータをそのまま返します |
| `SYS` | `INFO` | すぐ。版・`LOOPS`・CP15 の ID・取った依頼の数・出した知らせの数 |
| `SYS` | `PEEK` / `POKE` | すぐ。ARM から見た番地を 32/16/8 bit で読み書きします。アボートは `ABORT` |
| `SYS` | `EPTEST` | すぐ。EP `0x81` に 1 塊書く実験です（主 FR と同じ順）。状態を読んでから書くまでに DTCM を 4 回読みます（直後に書くと最初の語が消えることを実測しています） |
| `SYS` | `SUM` | あとで。範囲を 1 周 256 語ずつ読んで畳み込みます。時間はホストが計ります。読みの速さを測るためのものです |
| `WATCH` | `WAIT` | あとで。`([addr] & mask) == value` になったら `OK`、期限が来たら `TIMEOUT` |
| `WATCH` | `START` | すぐ（見張りの番号）。そのあと値が変わるたびに知らせ（`IPC_EVENT`）を出します |
| `WATCH` | `STOP` | すぐ。見張りの最後の知らせは `STOPPED` |
| `CARD` | `STATUS` | すぐ。段階・`CARD_EVENT`・`CARD_PINS`・`CARD_MODE`・ATR の長さ |
| `CARD` | `ON` | あとで。3 段の電源投入（段の間を 10 ms と 1 ms 待ちます）と ATR。答えの値が ATR の長さで、中身は置き場の受け側に入ります |
| `CARD` | `PARAM` | すぐ。`F`・`D`・`CWI` から速さと待ち時間を求めます（`card.c` の `CARD_PARAM` と同じ式） |
| `CARD` | `XFER` | あとで。置き場の送り側の 1 ブロックを送り、1 ブロック返ってきたら答えます。中身は受け側に入ります |
| `CARD` | `OFF` | すぐ。途中の仕事は `STOPPED` で答えます |

見張りは `WAIT` と `START` を合わせて 4 つまでです。カードの仕事は一度に 1 つです。

新しい仕事を足すときは、`svc_<名前>.c` を足し、`armipc.h` にサービスの番号を
足し、`armmain.c` の振り分けに 1 行足します。待つ仕事なら、`svc_watch.c` と同じく
「すぐ答えるか（1）、あとで答えるか（0）」を返し、ループの 1 歩を持たせます。
周辺を持つ仕事では、その周辺の持ち主が ARM になったことを `docs/` に書きます。

## 動かし方（GV-M2TV）

```
python3 host/build.py                 # build/armcore.bin も組む
cd sample && make
./frc1_load install ../build/frc1-m2tv.frc
./arm_probe hold
./arm_probe image ../build/armcore.bin
./arm_probe run                       # 'ARM1' を待つ
./arm_ipc demo                        # WAIT・ECHO・INFO を続けて積む
```

`demo` は、変わらない語への `WAIT`（期限つき）を先に積み、そのあと `ECHO` と
`INFO` を積みます。待っている仕事が後ろの仕事を止めないことを確かめるためのものです。
`ECHO` と `INFO` がすぐに答え、`WAIT` は期限が来てから `TIMEOUT` で答えます
（GV-M2TV の ARM-E・ARM-C で実測）。期限は周の数なので、秒に直すと 1 周の長さ
（上の「設計」）で変わります。

## 運び方

ARM のイメージはコンテナには入れていません。ホストが主 FR の `ARM_LOAD` で 32 バイトずつ
ITCM に書き、`ARM_RUN` で走らせます（`sample/arm_probe image` と `run`）。
dione では ITCM を主 FR から読めないので、入ったかどうかは走らせて郵便受けで確かめます。
FRC1 に ARM のイメージを入れて、主 FR が起動時に写す形はまだありません。

## まだ無いもの・未確認

- 仕事の輪は、GV-M2TV の ARM-E・ARM-C と PIX-DT295 の ARM-E で動きます（実測）。止め語
  （`ARM_CANCEL`）を実機で確かめたのは GV-M2TV の ARM-E・ARM-C だけです。検査は、主 FR 側が
  エミュレータ、ARM 側がホストの C（`tests/armcore_host.c`）で行います
- ARM のタイマー。`WAIT` の期限はループの回数で、秒ではありません（1 周の長さは仕事の量で
  変わります）
- 主 FR が ARM からの要因を割り込みとして受けること（要因を立てる口は分かっています）
- カードのサービス（`svc_card.c`）は、GV-M2TV と PIX-DT295 の ARM-E で動きます（ATR と
  S(IFS)、実測）。GV-M2TV では、PC/SC のドライバも ARM の経路（ARM-E・ARM-C）で ATR を取れます
  （[`../../sample/ifd/README.md`](../../sample/ifd/README.md)）
- selene では PIX-DT295 の ARM-E で走ります（[`../../docs/arm.md`](../../docs/arm.md) の「selene」）。
  DT295 の ARM-C は未確認です
- 符号化の側の周辺（`0x00E60000` 帯など）には触りません
