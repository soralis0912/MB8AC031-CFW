# 補助ユニット側のプログラム

`0x017` のユニットで走らせる、こちらのプログラムです。
主 FR 側の `CFW` とは別のイメージで、別の CPU に載ります（命令セットは同じ FR です）。

## 役割

補助ユニットのバスにある I2C コントローラ `0x01684FE0` を、補助ユニットの上で動かします。
主 FR は枠で転送を依頼します（`../main/i2c/auxslot.c`）。PIX-DT295 では、この経路で復調 IC が答えます（実測）。
今はどの機種の行もこの経路を選んでいません。DT295 の行は、主 FR から `0x00FD8FE0` を動かします。

| | |
|---|---|
| コントローラ | `0x01684FE0` 状態 / `+0x04` 制御 / `+0x08` 分周 / `+0x10` データ |
| その門（`AX_MODE_GATE` の形） | `0x01684010` と `0x01684014` に `0x0D000000`、そのあと `0x01684010 &= 0xF2FFFFFF`（実機では未確認） |
| 1 バイトの手順 | `../shared/fjcore.c` に実装があり、検査も通っています |
| 番地の見え方 | コードは局所 `0x000E0000`（主から `0x017E0000`）、RAM は局所 `0x000Axxxx`（主から `0x017Axxxx`）、周辺はどちらも素の番地 |

## I2C の状態機械

`fj_setup` / `fj_xfer`（`../shared/fjcore.c`）は、基底アドレスを引数に取る
ように書いてあります。このプログラムはそれをそのまま使います。
`tests/test_i2c.py` が検査しているのと同じコードが、同じように動きます。

## 電文の形

電文の形は `auxmain.c` にあります。`mb86m01.h` の `AUX_*` とは別の形です。
鈴も割り込みも使わず、補助コアは依頼の枠を見張ります。

## 置き場（aux SRAM の RAM の窓、実測）

| 番地 | |
|---|---|
| `0x017E0000` | 主 FR からは読むことも書くこともできません。起こす前も後も 0 を返します（実測） |
| `0x017A0000`..`0x017B0000` | 読み書きできます。16 KiB が `0x4000` ごとに鏡像になっています |

`link.ld` はイメージを `0x017A2D00` に置きます。RAM の窓に置けば、置けたかどうかを
主 FR から読み返して確かめられます。コード空間では確かめられません。

## ベクタ表

FR のリセットベクタは、そのユニットの空間の最後の語（`0x017FFFFC`）です。
主 FR がイメージを写したあと、そこへ `aux_entry`（局所の番地）を書きます
（`../main/i2c/auxslot.c`）。主 FR からは `0` が読めますが、コアは書いた値を受け取ります（実測）。

## 起こし方

コアは、いったん落としてから起こします（`../main/i2c/auxslot.c`。書く順は
[`../../docs/i2c.md`](../../docs/i2c.md) の「補助コアからの経路」の 2.）。
リセットが要る理由は未確認です。コアは電源投入時から走っていて、
運んだベクタを読み直さないのだと考えています。

### 枠の書き方

aux SRAM へのバイト書き込みは、もっと広い単位の read-modify-write になり、
その読みが古い値を返します（実測）。
枠の欄はどれも 4 の倍数なので、1 欄を 1 語で書きます。読めたバイトも語で
置きます（端は 0 で詰めます）。

## DT295 の形

PIX-DT295 で実測した形です。主 FR が形の語 `0x017A3F90` に `'CPW1'` を書いてから
コアを起こします（`../main/i2c/auxslot.c`）。今はどの機種の行もこの経路を選んでいません。
DT295 の行は、主 FR から `0x00FD8FE0` を動かします（`../main/i2c/fujitsu.c`）。この形では、立ち上げのときも転送のときも、
`0x00F1010C`（半語）を `0x000B` にしている間だけ帯 `0x0168` を触り、
終わったら元の値に戻します。帯の中では、`0x016840C0` を 0 にし、`0x01684010` の bit4 を立てて
`0x01684014` の bit4 を落とし、I2C の下位ブロックを起こします。詳しくは
[`../../docs/i2c.md`](../../docs/i2c.md) の「補助コアからの経路」にあります。

frc1 の経路では、ホストの窓が補助の RAM に届きません。そのため、このイメージは
`build/auxcore_image.c` として主のイメージに含め、主 FR が `0x017A2D00` へ写します。
形の語が `'CPW1'` でなければ、窓を開けずにコントローラを直接動かす形（`AX_MODE_GATE`）で動きます。この形は実機で動いたことがありません（未確認）。
