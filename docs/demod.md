# 復調（ロック、C/N、チューナーへの経路）

[`../src/main/demod/tc9052x.c`](../src/main/demod/tc9052x.c) の説明です。
機種ごとのアドレスは [`devices.md`](devices.md)、I2C の届け方は
[`i2c.md`](i2c.md) にあります。

## 復調 IC

このチップは復調をしません。復調は外付けのモジュールの中にあり、東芝の TC9052x 系
（TC90512 / 90517 / 90522 / 90532XBG）です。部品は別々ですがレジスタの構成は共通なので、
`config/devices/` はどれもこの 1 本のドライバを指しています。機種ごとに違うのは、
バスのアドレスとその確かさだけです。

## アドレス

| | 1 台目 | 2 台目 |
|---|---|---|
| 地上波 | `0x10` | `0x12`（推定） |
| 衛星 | `0x11` | `0x13`（推定） |

1 台目の `0x10` / `0x11` は、PIX-DT295 のバスの走査で実測した値です
（[`i2c.md`](i2c.md)）。2 台目の `0x12` / `0x13` は実測していません。
1 台目の隣の番地と見ています。いまの表（PIX-DT295・GV-M2TV）はどちらも 1 台だけで、
2 台目を持つ行はありません。

`source` の番号は `drivers.h` で決めています。

| `source` | | DT295 | 2 台の行（今は無い） |
|---|---|---|---|
| `FW_SRC_T` = 0 | 地上 1 台目 | `0x10` | `0x10` |
| `FW_SRC_T2` = 1 | 地上 2 台目 | — | `0x12` |
| `FW_SRC_S` = 2 | 衛星 1 台目 | `0x11` | `0x11` |
| `FW_SRC_S2` = 3 | 衛星 2 台目 | — | `0x13` |

持っていない台のアドレスは 0 なので、ドライバは `FW_ENOTIMPL` を返し、バスには
何も出しません。

## ロックと C/N のレジスタ

| | レジスタ | 判定 / 値の作り方 |
|---|---|---|
| 地上波のロック | `0x80` → `0xB0` | `0x80` に `0x28` のビットが 1 つでもあれば未ロック。無ければ `0xB0` を読んで、下位ニブルが 8 以上ならロック |
| 衛星のロック | `0xC3` | bit4 が落ちていればロック |
| 地上波の C/N | `0x8B`..`0x8D` | 3 バイトをビッグエンディアンに並べた 24 bit の生値 |
| 衛星の C/N | `0xBC`..`0xBD` | 2 バイトの 16 bit の生値 |

地上波の 2 つは実測です。GV-M2TV では、ロックの判定がホストの判定と一致し、C/N も読めます。
PIX-DT295 でも、選局の後にロックを返します。衛星の 2 つは未確認です（実機の衛星で `STATUS` を読んでいません）。

この 4 つはすべて読むだけです。バスに出る書き込みはレジスタ番号だけで、
値は 1 つも書きません（検査でこれを確かめています）。

### dB への換算

`demod_cnr_raw` が返すのは生のレジスタ値です。換算には部品ごとの表と曲線が要ります。
ここで換算を間違えると、ホストなら正しく換算できた値が失われるので、換算はホスト側で行います。

### 読みの失敗

バスが応答しないことと信号が弱いことは別なので、読みが失敗したら
`FW_EIO` を返します（`*locked = 0` にして `FW_OK` を返すことはしません）。ホストが
両者を区別できるようにするためです。

## 立ち上げ

`init` は、そのアドレスで何かが答えることを確かめるだけで、地上・衛星とも
`FW_ENOTIMPL` を返します。ロックの前に要る書き込みは、ホストが選局の列と一緒に
`I2CXFER` で送ります。

## チューナーへの経路（レジスタ `0xFE` のリピータ）

チューナーには復調 IC を経由して届きます。経由に使うのは復調のレジスタ `0xFE` で、
I2C のリピータになっています。

```
書き: 復調へ [0xFE, チューナーのアドレス << 1, ...データ]
読み: 復調へ [0xFE, (チューナーのアドレス << 1) | 1] を書いてから読む
```

これを行うのが `demod_tc9052x_gateway()` ですが、いまはどこからも呼んでいません。

ファームウェアの中には、リピータを開けた先で送る内容がないためです。
選局はホストが `I2CXFER` で `0xFE` を経由して送ります（GV-M2TV で実測）。
DT295 の MxL661 のレジスタ列も、ファームウェアは持ちません。

## まだ無いもの

| | |
|---|---|
| 地上・衛星の初期化の並び | ファームウェアには持たない。ホストが `I2CXFER` で送る（上） |
| DT295 のチューナーのレジスタ列 | 無い。ファームウェアは I2C を中継するだけで、列はホストが持つ |

## 検査

[`../tests/test_i2c.py`](../tests/test_i2c.py) は、モデル化した I2C の相手に
レジスタを持たせて、ファームウェアがどのレジスタをどの順で読むかを確かめます。

| 確かめていること |
|---|
| 地上波: `0x80`/`0xB0` の 5 通りの組でロックの判定が合う |
| `0x80` で未ロックと分かったら `0xB0` は読まない |
| 衛星: `0xC3` の bit4 だけを見ている（`0xEF` でロック、`0xFF` で未ロック） |
| 地上波の C/N が 24 bit、衛星が 16 bit の値になる |
| 1 レジスタずつ番号を送って 1 バイト読む（地上 3 回・衛星 2 回） |
| 返事が無ければ `FW_EIO`。未ロックとして返さない |
| アドレスが無い行（`unknown`）ではバスに何も出さない |
| バスに出た書き込みはレジスタ番号だけで、値は 1 つも書かない |

実機での確かさは、上の「ロックと C/N のレジスタ」のとおりです。衛星は未確認です。

## 誤りの数

`STATUS` は誤りの数を持ちません。dione では、誤りを TS の TEI（2 バイト目の bit7）で数え、
`STREAM` の報告の `+0x1C` がその数です（[`frq1.md`](frq1.md) の「dione（GV-M2TV）の場合」）。
selene の `STREAM` の報告には誤りの数がありません。
