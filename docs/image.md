# イメージの形

実装は [`../src/main/resident.h`](../src/main/resident.h) と
[`../src/main/link_selene.ld`](../src/main/link_selene.ld)・
[`../src/main/link_dione.ld`](../src/main/link_dione.ld) で、この文書はその説明です。

## メモリマップ

selene のファームウェアは `0x80380000` からの 256 KiB の中に収まります。この並びは
ただのメモリマップで、ほかの何かと取り決めたものではありません。
コードと書き換わるものは分けて置きます。走ったあとのメモリを差分で見れば、
static が `.text` に落ちていないかが分かります。また、`frc1` は `.bss` を 0 の
セグメントとして宣言するので、`.bss` は 1 かたまりにしてあります。

dione（MB8AC018 / GV-M2TV）は `0x80380000` を使いません。ローダ状態では外部
メモリーが落ちていて `0x80380000` に届かないので、配置は `link_dione.ld` が決めます
（[`frc1.md`](frc1.md) の世代表）。dione の配置は次のとおりです。

| 名前 | 値 | 役 |
|---|---|---|
| `RES_BASE` | `0x000E1800` | コード。`0x000E9000`（機器の常駐ローダ）の手前まで、約 30 KiB |
| `RES_IMMUT_END` | `0x000E9000` | コードの上限 |
| 郵便受け | `0x000C5000` / `0x000C5040` / `0x000C5080` / `0x000C50C0` | 64 B の `FRQ1` の枠が 4 つ。ホストのプログラムごとに 1 つ使います（[`frq1.md`](frq1.md) の dione の節） |
| `RES_BSS` | `0x000C5100` | `.bss` |
| `RES_META` | `0x000C5800` | `.bss` の上限 |
| `RES_STACK_TOP` | `0x000C5FF8` | スタックの頂。郵便受けと同じページにあります |

書き換わるものを `0x000C` 帯に置いているのは、`0x000E` 帯では語より狭い書き込みが
壊れるからです。GV-M2TV で、語 `0x11223344` に次の書き込みをして読み戻した値は次のとおりです。

| 書き込み | `0x000E7000` | 正しい値 |
|---|---|---|
| 半語 `0xAABB` を `+0` | `0xAABB00BB` | `0xAABB3344` |
| 半語 `0xCCDD` を `+2` | `0x0000CCDD` | `0x1122CCDD` |
| 1 バイト `0xEE` を `+1` | `0x00EE00EE` | `0x11EE3344` |

語の残りの部分は保たれません。`0x000C5000` のページでは、1 バイトずつ書いても正しく残ります。
コンパイラはスタックと `.bss` に `stb` / `sth` を自動で出すので、型の工夫では
避けられません。そのため、書き換わるものは `0x000C` 帯に置きます。コードは読むだけなので、
`0x000E` 帯に置きます。

`0x000C5040`〜`0x000C5FFF` は常駐ローダが使っていない領域で、電源投入時の値は不定です
（GV-M2TV で実測）。スタックは `RES_STACK_TOP` からこの領域の中へ下に伸びます。

`tests/test_i2c_dione.py` と `tests/test_card.py` は、この挙動をエミュレータに
組み込み、`0x000E` 帯への狭い書き込みが 1 回も無いことを確かめます。

ここから下は `selene`（MB8AC031）の話です。

| 名前 | 値 | 役 |
|---|---|---|
| `RES_BASE` | `0x80380000` | コードの置き場。`_start` と `.text` |
| `RES_IMMUT_END` | `0x803B0000` | ここから上が `.bss`。下はコードだけ |
| `RES_META` | `0x803BEFE0` | `.bss` の上限 |
| `RES_STACK_TOP` | `0x803BFFF8` | スタックの頂。`.bss` より上 |

`0x8xxxxxxx` は低位メモリのキャッシュ側のビューで、別の領域ではありません
（物理アドレスは `& 0x3FFFFFFF`）。ホストに見せたいものは素の番地へ書きます。

### コードの領域と書き換わるもの

走っているあいだに書き換わるものは、コードの範囲に置きません。
置かれていないことは、`tests/test_frq1.py` が走ったあとのメモリの差分で
確かめています。該当するのは次の 2 つです。

| | 置き場 |
|---|---|
| スタック | `RES_STACK_TOP` から下へ。不変領域より上 |
| `.bss`（static 変数） | `RES_IMMUT_END` から上。[`../src/main/link_selene.ld`](../src/main/link_selene.ld) が配置します |

`.bss` は `NOLOAD` です。平たい出力には入らず、配布するイメージではその部分が 0 に
なっています。256 KiB の 0 で埋めたバッファにコードだけを入れて作るためです。
そのため、起動時の 0 クリアは要りません。

`.bss` が不変領域の中に置かれると、枠を 1 つ処理するだけでコードの領域が書き換わります。
`tests/test_frq1.py` は、走ったあとに不変領域が 1 語も動いていないことを確かめます。

### `.data` を持てないこと

初期値つきの書き換え可能なデータを置く場所はありません。置くとすれば不変領域に
入れるしかなく、そこには書き込めません。`const` にして `.rodata`
（`.text` の中）へ置くか、実行時に代入します。リンカが `ASSERT` で
止めるので、気づかずに通ることはありません。

## 入口

入口は `_start` と `frc1_entry` の 2 つで、どちらもアセンブリです。`frc1_entry` は世代ごとに
1 本あります。実機で通っているのは `frc1_entry` のほうです（[`frc1.md`](frc1.md)）。

| 入口 | 誰が呼ぶか | 実機 |
|---|---|---|
| `_start`（[`../src/main/entry.S`](../src/main/entry.S)） | `call 0x80380000`（エミュレータの検査だけ） | 未 |
| `frc1_entry`（[`../src/main/entry_frc1_selene.S`](../src/main/entry_frc1_selene.S)） | 常駐ローダの hook（selene） | PIX-DT295 で通っている |
| `frc1_entry`（[`../src/main/entry_frc1_dione.S`](../src/main/entry_frc1_dione.S)） | 常駐ローダの hook（dione） | GV-M2TV で通っている |

`frc1_entry` の中身は [`frc1.md`](frc1.md) の「`CFW` の載せ方」にあります。

### `_start`

`call 0x80380000` で入ってくる経路です。いまの経路でこれを呼ぶものはありません。
`tests/test_frq1.py` がエミュレータで `RES_BASE` から直接呼んでいます。
大きさは 24 バイトです。

FR の `call` の決まりで、
戻り番地は `RP` にあります。`r4` には枠の番地が入っています。処理は次の 3 つです。

1. `RP` を積む（`call` で上書きされるため）
2. 元の `r15` を覚えて、スタックを `RES_STACK_TOP` に切り替える
3. `frq1_dispatch` を呼び、戻ったらすべて元に戻して `ret`

スタックを切り替えるのは、呼び出し元が渡してくるスタックにどれだけ余裕があるか分からない
ためです。C では書けないので、ここだけアセンブリにしています。
