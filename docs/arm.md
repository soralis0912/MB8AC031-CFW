# ARM の 2 基

このチップには、FR の横に ARM のコアが 2 基あります（ARM-E と ARM-C）。この文書は、
そこに自分のプログラムを載せて走らせるための仕様です。

こちらのイメージは、GV-M2TV（dione）の ARM-E・ARM-C と、PIX-DT295（selene）の ARM-E で
走ります（実測）。主 FR の帯 `0x60` だけで、コアを止め、ITCM にイメージを書き、走らせ、
郵便受けで依頼を受けて答えさせます。イメージは郵便受けの依頼で任意の番地を読み書きできるので、
ARM から見える番地もこの依頼で測れます（下の「ARM から見た番地」）。selene での違いは
下の「selene」にあります。

## 走らせ方

```
./arm_probe hold                        # 帯を起こし、止めて、リセットに留める
./arm_probe image ../build/armcore.bin  # ITCM の 0 から 32 バイトずつ
./arm_probe run                         # ARM_RUN。'ARM1' が出るまで待つ
./arm_probe ask 0x12345678              # 郵便受けで 1 往復（答えは ~引数）
./arm_probe rd 0x00f10118               # ARM に読ませる（--w 16 / 8 も）
./arm_probe wr 0x00e70404 4 --w 16      # ARM に書かせて読み返させる
./arm_probe cp15                        # ARM の CP15（ID・キャッシュ・TCM）
./arm_probe hold                        # 止める
```

どのコマンドも、`--core 1` を付けると ARM-C が相手になります。

`run` は郵便受けに `'ARM1'` が出るまで待ちます。`ask` の答えは引数のビット反転です
（`0x12345678` なら `0xEDCBA987`）。

## 番地

同じ RAM が、主 FR と ARM では違う番地に見えます。ARM のイメージは、ARM 自身から
見た番地でリンクします。

| ARM から | 主 FR から（ARM-E / ARM-C） | 中身 |
|---|---|---|
| `0x00000000`〜`0x0000FFFF` | `0x00E00000` / `0x00C00000` | ITCM。ベクタ表から始まるイメージを置きます。主 FR からは書けますが読めません（いつも `0` を読みます） |
| `0x00100000`〜`0x0010FFFF` | `0x00E80000` / `0x00C80000` | DTCM。`.bss`・スタック・郵便受けを置きます。主 FR から読み書きできます |
| — | `0x00E40000`〜`0x00E57FFF` | RAM（96 KiB）。このファームウェアは使いません |
| — | `0x00E70000`〜 | 制御帯（16 bit のレジスタ） |

ITCM が番地 0、DTCM が `0x00100000` であることは実測です（GV-M2TV、ARM-E）。
イメージは `0` にベクタを置き、DTCM を `c9,c1,0` で `0x00100000` に置いて郵便受けを書きます。
命令は ITCM から取ります。RAM `0x00E40000` の写しを 0 で潰しても走ります（実測）。

ITCM と DTCM の大きさ（どちらも 64 KiB と置いています）は未確認です。CP15 の領域レジスタの大きさの欄は、ITCM が `0x9`、DTCM が `0xB` です
（下の表）。

### コア（CP15、ARM が読んだ値。GV-M2TV で実測、2 基とも同じ）

| レジスタ | 値 | 読み |
|---|---|---|
| `c0,c0,0` main ID | `0x41069265` | ARM926EJ-S（ARMv5TEJ、r0p5） |
| `c0,c0,1` cache type | `0x1D112112` | 命令・データとも 8 KiB、4 way、32 バイトの行 |
| `c0,c0,2` TCM status | `0x00010001` | ITCM と DTCM がある |
| `c1,c0,0` control | `0x000500F8` | MMU・キャッシュとも切れていて、ベクタは下位 |
| `c9,c1,0` DTCM region | `0x0010002D` | `0x00100000`・有効・大きさの欄 `0xB` |
| `c9,c1,1` ITCM region | `0x00000025` | `0`・有効・大きさの欄 `0x9` |

大きさの欄の読み方（何 KiB か）は、TRM と突き合わせていません。

## ARM から見た番地（GV-M2TV で実測、ARM-E と ARM-C）

根拠の欄は、ARM に郵便受けの依頼で読ませた値と、同じ番地を主 FR の `PEEK` で読んだ値の
比べです。

| ARM の番地 | 届く先 | 根拠 |
|---|---|---|
| `0x00F0xxxx`・`0x00F1xxxx`・`0x00FDxxxx`・`0x00FEA000`・`0x0160xxxx` | 主 FR と同じ周辺（ホスト窓・ピン・`0x00FD8010`・カード・ユニット `0x016`） | 値が一致 |
| `0x00F40000`〜 | 主 SRAM の `0x000C0000`〜 | ARM の `0x00F45000` が主の `0x000C5000`（FRQ1 の枠）と一致。`0x00F41000`・`0x00F4E000` も一致 |
| `0x0xxxxxxx`（例 `0x02000000`） | DRAM の物理番地 | 主の `0x02000000`（`'MB8A'`）と一致 |
| `0x8xxxxxxx` | どこにもつながっていない | どこを読んでも `0x270FA703` で、アボートしない |
| `0x000E1000`・`0x000C5000` | 主 SRAM ではない | `0` を読む |
| `0x00E00000`〜`0x00EFFFFF` | 自分の窓（制御帯・RAM・DTCM の窓） | 2 基とも。ARM-C の `0x00E8FF04` は ARM-C 自身の `loops` |
| `0x00C00000`〜`0x00CFFFFF` | もう一方のコアの窓 | ARM-C の `0x00C8FF04` は ARM-E の `loops`、ARM-E の `0x00C8FF04` は ARM-C の `loops` |

ARM から見ると、番地 `0x00E...` が自分、`0x00C...` が相手です。主 FR から見ると、`0x00E...` が ARM-E、
`0x00C...` が ARM-C です。

## 主 FR から見た制御帯

| 番地（ARM-E） | 幅 | 何が分かっているか |
|---|---|---|
| `0x00F10118`（上半分） | 16 | `0xFFFF` を書くと 2 基の制御帯が起きます（実測）。TS の経路（`ts_dione.c`）も同じ値を書きます |
| `0x00E70000` | 16 | bit0 がコアを止めます（実測）。立っていると郵便受けの輪の数が止まり、落とすと走ります。帯が起きた直後は `0x0001`（止まっている）です。`7` を書いても `0x0001` しか残りません |
| `0x00E70004` | 16 | リセット。`0xFFFF` を書くと `0x0FFF` を読みます。走っているコアは `0x0FFF` だけでは止まりません（実測）。コアではなく ARM 側の周辺ブロックのリセットと見ています（未確認）。止めてから `0x0FFF` → `0x0104` にして `+0` の bit0 を落とすと、ITCM の 0 から走り直します |
| `0x00E70014` | 16 | ARM 側の割り込み要因と見ています（未確認）。bit1 が `0x00E70034`、bit2 が `0x00E78050`、bit3 が `0x00E58000` に対応する見込みです |
| `0x00E70034` | 16 | 主 FR からの命令が届く所です（実測）。主 FR が `0x00E70050 = 1` を書くと、ARM の `0x00E70034` が `1` を読みます |
| `0x00E70050` | 16 | 主 FR から ARM への命令です（書き込み専用。主 FR からは `0` を読みます） |
| `0x00E58000` | 16 | 制御語。役は未確認です |
| `0x00E70404` | 16 | 読むと `0x0004`。ARM から書いた値が主 FR から見えます（実測。`2` を書くと `0x0002`）。状態を見せる語の見込みです |
| `0x00FD0038` / `0x00FD0048` | 16 | ARM-E から主 FR への割り込みの要因（書いて消す）と許可です。ARM-C は `0x00FD0034` / `0x00FD0044`。クロックの門ではありません |
| `0x00FD0054` / `0x00FD0050` | 16 | ARM-E / ARM-C が要因を立てる口です。書いたビットが `0x00FD0038` / `0x00FD0034` に立ちます（GV-M2TV で実測） |

DTCM が主 FR から見えるかどうかは、`+4` の値で変わります（実測）。`0x0FFF` と `0x0104` では
見え、走っている間も読めます。`0` では `0` しか読めません。

ARM-C の制御帯は `0x00C7xxxx`・`0x00C58000` です。確かめてあるのは読めることだけです
（`0x00C70000` も `0x0001` を読みます）。

ITCM を埋めるには、`+4 = 0xFFFF` のあと窓 `0x00E00000` へ語で書けば足ります
（`ARM_LOAD`）。走らせるには `+4 = 0x0104`、`+0 &= ~3` とします（`ARM_RUN`）。
`+0 = 7`、`+4 = 0` では走りません（GV-M2TV で実測）。

## 割り込み

- 主 FR → ARM は動きます（上の `0x00E70050` → `0x00E70034`）。ARM は割り込みを
  使わず、`0x00E70034` を読んで知ります。ARM の IRQ（`0x00E70014`）にはまだつないでいません
- ARM → 主 FR は、ARM が要因を立てられます（GV-M2TV で実測）。ARM-E が `0x00FD0054` に
  16 bit で 1 ビット書くと、主 FR の `0x00FD0038` の同じビットが立ちます。ARM-C では `0x00FD0050`
  → `0x00FD0034` です。主 FR がそのビットを要因に書くと消えます。要因は許可
  （`0x00FD0044`・`0x00FD0048`）が `0` でも立ちます。確かめたビットは、ARM-E の `0x08`・`0x40` と
  ARM-C の `0x08` です
- 許可を立てて、主 FR がその要因を割り込みとして受ける形は未確認です。主 FR は割り込みの
  入口を持っていません。いまの主 FR は割り込みを使わず、郵便受けと仕事の輪を読みます

## 郵便受け

DTCM の最後の 256 バイトです。ARM 側では `0x0010FF00`、主 FR 側では `0x00E8FF00`（ARM-E）に見えます。
形はこちらで決めました。どの欄も 1 語（ビッグエンディアン）です。

| 相対 | 書く側 | 中身 |
|---|---|---|
| `+0x00` | ARM | `'ARM1'`（`0x41524D31`）。こちらのイメージの `arm_main` が走った印 |
| `+0x04` | ARM | 輪を回るたびに増える |
| `+0x08` | ARM | 例外の印。`0x46000000` + ベクタ番号（1 = 未定義命令 … 7 = FIQ） |
| `+0x0C` | ARM | 例外のときの `lr` |
| `+0x10` | 主 | 依頼の連番。変われば新しい依頼 |
| `+0x14` | 主 | 依頼の引数 |
| `+0x18` | ARM | 答えた依頼の連番 |
| `+0x1C` | ARM | 答え |
| `+0x20` | 主 | 依頼の種類（下） |
| `+0x24` | 主 | 書く値 |
| `+0x28` | ARM | 答えの状態。`0` よい、`1` データアボート、`2` 知らない種類 |
| `+0x2C` | ARM | 番地を触る間だけ `1`（アボート処理が見る） |
| `+0x30` | ARM | アボート処理の退避場所 |
| `+0x34`・`+0x38` | ARM | 最後のアボートの FAR・FSR |

| 種類 | 中身 |
|---|---|
| `0` | 答え = 引数のビット反転 |
| `1`・`3`・`5` | 引数の番地を 32・16・8 bit で読む |
| `2`・`4`・`6` | 引数の番地に書く値を 32・16・8 bit で書き、読み返す |
| `7` | CP15 を読む。引数 `0` ID・`1` キャッシュ・`2` TCM・`3` control・`4` DTCM 領域・`5` ITCM 領域 |

アボートしてもイメージは止まりません。`+0x2C` が `1` の間のデータアボートは、FAR と
FSR を書いて次の命令へ戻ります（`vectors.S`）。書き込みでは、読み返す前にアボートしていない
かを確かめます。

ARM は答えを書いてから連番を書きます。主 FR は引数を書いてから連番を書き、
連番が返ったのを見てから答えを読みます。ARM のスタックは郵便受けのすぐ下
（`0x0010FF00`）から下へ伸びます。

DTCM は電源投入時の不定な値を持っています。`ARM_RUN` は `+0x00` と
`+0x08` を消してから走らせます。`+0x10` も古い値のままなので、ARM は走り出して
すぐ、その値を依頼と見て 1 回答えます（実害はありません。`ask` は答えた連番 + 1 を使います）。

## selene

ARM の帯の扱いは dione と同じ形です。窓（`0x00E00000` / `0x00C00000`）、
`+0`・`+4` による起動（`+4 = 0x0104`・`+0 &= ~3`）と停止、写す前の `+4 = 0xFFFF` は共通です。
違うのは帯を起こす手順です。

selene の `ARM_HOLD`（`arm_selene.c`）は、`0x00F10118 = 0xFFFF` とそのコアの
`+0x404 |= 4` を行い、門を開けたままにします。読んだ値に戻すと帯が見えなく
なります（PIX-DT295 で実測）。`0x00F10090` には触りません（主 FR から `0x00F10080`〜
`0x00F100FF` を読むと走っているイメージが止まるという実測があります。`src/shared/mb86m01.h`）。
`0x00F1011C` も変えません。

ホストの道具は `--dev dt295` で DT295 を開きます（[`../sample/cfwdev.h`](../sample/cfwdev.h)）。
`arm_probe`・`arm_ipc` は selene の郵便受け 2（`0x003B0080`）を使います。
カードのドライバ（1）や `ts_grab`（0）と同時に走らせても構いません
（[`frq1.md`](frq1.md)）。

## コマンド（帯 `0x60`）

実機で動くのは、GV-M2TV（dione）の 2 基と PIX-DT295（selene）の ARM-E です。
DT295 の ARM-C と、DT295 での `ARM_CANCEL` は未確認です。引数 0 の下位 8 bit でコアを選び、
`0` が ARM-E、`1` が ARM-C です。どのコマンドも 2 基とも受けます。

| 値 | 名前 | 状態 | 中身 |
|---|---|---|---|
| `0x60` | ARM_STATUS | 実機で動く（GV-M2TV・PIX-DT295） | 読むだけ。報告は下 |
| `0x61` | ARM_HOLD | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | dione: `0x00F10118` を `0xFFFF` にする（下半分は残す）。selene: `0x00F10118` を `0xFFFF` にして `+0x404 \|= 4`。`0x00F10118` は開けたままにする（下の「selene」）。続けて `+0 \|= 1`（止める）、`+4 = 0xFFFF`。止まって留まっていなければ `FW_EIO`。報告は STATUS と同じ |
| `0x62` | ARM_LOAD | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 引数 0 = コア ∣ バイト数 ≪ 8、引数 1 = ARM から見た番地。データ欄の語を書く。DTCM は読み返す |
| `0x63` | ARM_RUN | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 留めていなければ `FW_EAGAIN`。郵便受けの `+0x00`・`+0x08` と仕事の輪の見出しを消し、`+4 = 0x0104`、`+0 &= ~3`。待たない。報告は STATUS と同じ |
| `0x64` | ARM_CALL | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 仕事の輪に依頼を 1 つ積む。引数 0 = コア ∣ `IPC_CALL(サービス, 操作)` ≪ 8、引数 1 = 依頼の `ARG0`、データ欄 = `ARG1` と 4 語。輪が満ちていれば `FW_EAGAIN`、ARM が `'IPC1'` を出していなければ `FW_EIO`。報告: `+4` 依頼の番号（SEQ）、`+8` 待っている依頼、`+12` 待っている答え |
| `0x65` | ARM_REAP | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 答えを 1 つ出す。無ければ `FW_EAGAIN`。報告: `+4` SEQ、`+8` CALL（知らせなら `0x80000000` が立つ）、`+12` 状態、`+16` 値、`+20`〜`+35` 4 語、`+36` 残りの答え |
| `0x66` | ARM_CANCEL | 実機で動く（GV-M2TV、2 基） | 止め語。引数 1 = SEQ（その仕事を答え無しで終わらせる）か `0xFFFFFFFF`（全部。取っていない依頼も捨てる）か `0`（読むだけ）。輪の状態に関係なく効く。前の止めが済んでいなければ `FW_EAGAIN`、イメージが聞いていなければ `FW_EIO`。報告: `+4` CANCEL_REQ、`+8` CANCEL_ACK、`+12` 終わらせた数、`+16` 捨てた数、`+20` 待っている依頼、`+24` 待っている答え |
| `0x67` | ARM_PUT | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 置き場（下）の送り側へバイトを書く。引数 0 = コア ∣ バイト数（1〜40）≪ 8、引数 1 = 送り側の中の位置（4 の倍数）、データ欄 = バイト。依頼を積む前に書く |
| `0x68` | ARM_GET | 実機で動く（GV-M2TV は 2 基、PIX-DT295 は ARM-E） | 置き場の受け側から 40 バイト読む。引数 1 = 位置（4 の倍数）。端より先は 0。それを示す答えを取った後に読む |

`ARM_CALL`・`ARM_REAP` の輪の形とサービスは [`../src/shared/armipc.h`](../src/shared/armipc.h)、
設計は [`../src/armcore/README.md`](../src/armcore/README.md) にあります。`ARM_HOLD` も輪の見出しを消します（止めたコアは依頼を聞いていないため）。

### 置き場

1 枠のデータは 4 語しかありませんが、カードの 1 ブロックは 259 バイトまであります。そこで
大きいものは輪の下の 0x400 バイト（ARM から `0x0010F600`、主 FR から窓の
`+0x8F600`）に置き、枠では長さだけを伝えます。前半 `0x200` は主 FR だけが書く送り側、
後半 `0x200` は ARM だけが書く受け側です。バイトは語の値として上位から詰めます
（バイト `i` は語 `i/4` の上から `i%4` 番目）。両方とも語でしか触らないので、
バスがバイトをどう並べるかに左右されません（[`../src/shared/armipc.h`](../src/shared/armipc.h)）。

### カードの持ち主

カードのブロックは、主 FR の `card.c` か ARM の `svc_card.c` のどちらか一方が
持ちます。決めるのは主 FR の `arm_ipc.c` です（全部の依頼がそこを通るため）。

- `ARM_CALL` でカードの `ON` を積むと、そのコアが持ち主になります。`OFF` を積むか、
  そのコアを `ARM_HOLD`・`ARM_RUN` すると外れます
- ARM が持っている間、`card.c` のコマンドは `CARD_STATUS` 以外 `FW_EBUSY` を返します
- `card.c` が電源を入れている間（段階が 0 でない間）と、もう一方のコアが持って
  いる間は、カードの `ON`・`PARAM`・`XFER` を積むと `FW_EBUSY` を返します

主 FR は ARM の窓を読まずにこれを決めます。帯が起きていなくても読みに行きません。

### ARM_STATUS の報告

| 相対 | 中身 |
|---|---|
| `+0` | 版（1）・コア・旗・0。旗は bit0 起きている（`+0` か `+4` が 0 でない）、bit1 留めている（`+0` の bit0 と `+4 = 0x0FFF`）、bit2 `'ARM1'` がある、bit3 例外の印がある、bit4 走っている（起きていて `+0` の bit0 が 0） |
| `+4` | `0x00F10118` の上半分 |
| `+8` | `+0` ≪ 16 ∣ `+4` |
| `+12` | `0x00x58000` ≪ 16 ∣ `+0x404` |
| `+16`〜`+36` | 郵便受けの `+0x00`〜`+0x0C`・`+0x18`・`+0x1C` |

`+0` は走っている間 `0` を読むので、bit0（起きている）は `+4` も見て決めます。

### ARM_LOAD

- バイト数は 4〜32 で 4 の倍数です。番地は 4 の倍数で、ITCM（`0`〜`0xFFFF`）か
  DTCM（`0x00100000`〜`0x0010FFFF`）に収まる必要があります。外れれば `FW_EINVAL` を返します
- コアを留めていなければ `FW_EAGAIN` を返します（先に `ARM_HOLD` が要ります）
- 1 語ずつ書きます。DTCM は読み返し、食い違いがあれば `FW_EIO` を返します。
  ITCM は読み返しません（dione の主 FR からはいつも `0` を読むため。selene の PIX-DT295 では読み返せます。実測）。入ったかどうかは走らせて確かめます
- 報告: `+0` 版・コア・書いた語数・最初に食い違った語の位置（無ければ `0xFF`）、
  `+4` 番地、`+8` その語の読み値

## TS を流すコア

EP `0x81` と端点のレジスタの窓は、EP0 に答える主 FR が扱います。ARM は EP に
書きません（`SYS.EPTEST` は測るためだけの操作です）。EP0 の転送と同じ窓を触るので、
別のコアから書くと、重なったときに TS が欠けます（GV-M2TV で実測）。
